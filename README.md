# Онлайн-запис у барбершоп: Telegram-бот і веб-адмінка

Бот для онлайн-запису: клієнт обирає послугу, майстра й вільний час, а за добу і за дві години до візиту отримує нагадування. Майстри бачать свої записи в Telegram, адміністратор керує послугами, майстрами й графіком у веб-адмінці.

**Склад:** Telegram-бот (aiogram 3) · веб-адмінка (FastAPI) · PostgreSQL · щоденні бекапи. Усе запускається однією командою через Docker Compose.

---

## Перший запуск на сервері (Ubuntu 24.04)

1. Встановіть Docker: `curl -fsSL https://get.docker.com | sh`
2. Завантажте код і перейдіть у папку:
   ```bash
   git clone <адреса репозиторію> barber-bot && cd barber-bot
   ```
3. Створіть файл налаштувань і заповніть його:
   ```bash
   cp .env.example .env
   nano .env
   ```
   Обов'язково заповніть:
   - `BOT_TOKEN` — токен від @BotFather;
   - `POSTGRES_PASSWORD` і `ADMIN_PASSWORD` — будь-які надійні паролі;
   - `ADMIN_SECRET_KEY` — результат команди `openssl rand -hex 32`;
   - `ADMIN_TELEGRAM` — @username адміністратора в Telegram.
4. Запустіть:
   ```bash
   docker compose up -d --build
   ```
5. Внесіть в адмінці послуги, майстрів і їхній графік (див. «Як відкрити адмінку» і «Часті дії» нижче). Якщо ці дані вже є в Excel-таблиці, їх можна завантажити однією командою — див. розділ «Стартові дані з Excel».
6. Адміністратор і кожен майстер мають відкрити бота і натиснути **/start**. Без цього Telegram не дозволить боту писати їм першим. Після цього бот відповість «Готово, ви в системі як…».

Перевірка: `docker compose ps` — сервіси `bot`, `admin`, `db`, `backup` мають статус `Up`.

## Як відкрити адмінку

Адмінка доступна лише з самого сервера (порт 8000). Є два способи потрапити в неї.

**З доменом (рекомендовано).** Спрямуйте домен (наприклад, `admin.example.com`) на IP сервера і додайте в `.env`:
```
COMPOSE_PROFILES=https
ADMIN_DOMAIN=admin.example.com
ADMIN_HTTPS_ONLY=true
```
Потім виконайте `docker compose up -d`. HTTPS-сертифікат налаштується автоматично. Адмінка: `https://admin.example.com`.

**Без домену.** На своєму комп'ютері відкрийте SSH-тунель і зайдіть у браузері на `http://localhost:8000`:
```bash
ssh -L 8000:localhost:8000 user@IP-сервера
```

Логін і пароль — `ADMIN_LOGIN` і `ADMIN_PASSWORD` з `.env`.

## Часті дії

### Змінити токен бота
1. У `.env` замініть `BOT_TOKEN=...` на новий токен.
2. Виконайте `docker compose up -d bot`.

### Додати майстра
1. Адмінка → **Майстри й графік** → **+ Додати**: ім'я, Telegram (`@username`), послуги, які він виконує → **Зберегти**.
2. На сторінці майстра заповніть **Тижневий графік** → **Зберегти графік**.
3. Попросіть майстра відкрити бота і натиснути **/start**. Біля його імені з'явиться позначка «підключено».

Майстер одразу з'являється в боті. Щоб тимчасово прибрати майстра, зніміть галочку «Приймає записи».

### Вихідний, скорочений день, відпустка
Сторінка майстра:
- **Окремі дні** — інші години або вихідний на конкретну дату;
- **Відпустки** — діапазон дат.

### Обід або інша перерва
Меню **Перерва**: майстер, дата, час. Цей час зникне з бота.

### Клієнт подзвонив
Меню **+ Запис**: оберіть послугу, майстра (або «будь-який») і дату → **Вільний час** → оберіть час, введіть ім'я й телефон → **Записати**. Майстер отримає сповіщення.

### Послуги й ціни
Меню **Послуги**. Послугу не видаляють, а вимикають (галочка «Показувати в боті»). Нову послугу позначте в картках майстрів, які її виконують.

### Контакти, адреса, точка на карті
Змінюються в `.env` (`SHOP_*`), після чого потрібен `docker compose up -d`.

## Стартові дані з Excel (необов'язково)

Замість ручного введення в адмінці послуги, майстрів і тижневий графік можна завантажити з таблиці.

1. Підготуйте файл за описом у [data/README.md](data/README.md) і покладіть його в `data/shop_data.xlsx`. У репозиторії цього файлу немає.
2. Виконайте:
   ```bash
   docker compose run --rm -v "$PWD/data:/app/data:ro" bot python -m app.scripts.seed
   ```

Якщо послуги в БД уже є, скрипт нічого не змінить. З `--force` він перезапише послуги, майстрів і тижневий графік з файлу. Записи клієнтів, окремі дні й відпустки при цьому залишаться.

## Бекапи

Щодня створюється архів БД у папці `backups/`. Архіви зберігаються 14 днів. Рекомендовано також копіювати їх за межі сервера.

Відновлення з архіву. **Поточні дані в БД буде замінено вмістом архіву:**
```bash
docker compose stop bot admin
docker compose exec -T db dropdb -U barber barber
docker compose exec -T db createdb -U barber barber
gunzip -c backups/db-РРРР-ММ-ДД.sql.gz | docker compose exec -T db psql -q -U barber -d barber
docker compose start bot admin
```

## Для розробника

```bash
uv sync                          # залежності
uv run pytest -q                 # тести (піднімають PostgreSQL у Docker)
uv run ruff check . && uv run ruff format .
```

Без uv (Python 3.12):
```bash
pip install -r requirements.txt       # для роботи
pip install -r requirements-dev.txt   # для роботи + тести й лінтер
```
Ці файли згенеровано з `uv.lock`. Після зміни залежностей їх треба перегенерувати:
```bash
uv export --frozen --no-dev --no-hashes --no-emit-project -o requirements.txt
uv export --frozen --no-hashes --no-emit-project -o requirements-dev.txt
```

Локально без Docker для застосунку: підніміть PostgreSQL, вкажіть `DATABASE_URL` у `.env`, далі:
```bash
uv run alembic upgrade head
uv run python -m app.scripts.seed --demo   # дані з data/shop_data.xlsx + демо-записи
uv run python -m app.bot                   # бот
uv run uvicorn app.admin.main:app --reload # адмінка
```

### Запуск із VS Code

Потрібні Docker, `uv sync` і розширення Python (VS Code запропонує встановити рекомендовані). У `.env` має бути `BOT_TOKEN`.

1. **Run and Debug** (Ctrl+Shift+D) → оберіть конфігурацію → **F5**:
   - **Бот + нагадування** — `python -m app.bot`;
   - **Адмінка (localhost:8001)** — http://localhost:8001, логін/пароль з `.env`; при зміні коду в `app/` сервер перезапускається сам;
   - **Бот + адмінка** — обидва разом;
   - **Заповнити БД (seed --demo)** — дані з `data/shop_data.xlsx` і два демо-записи на найближчий вільний час (повторно нічого не дублює).
2. Перед кожним запуском VS Code сам піднімає окрему PostgreSQL у Docker (`docker-compose.dev.yml`, localhost:5432, `barber`/`barber`) і застосовує міграції. Ця БД не пов'язана з основним стеком із `docker-compose.yml`.

Задачі (Ctrl+Shift+P → **Tasks: Run Task**): `Dev DB: зупинити`, `Тести`, `Ruff`. Видалити dev-БД разом із даними: `docker compose -f docker-compose.dev.yml down -v`.

Не запускайте бота з VS Code, поки працює контейнер `bot` з тим самим токеном: Telegram віддає оновлення лише одному процесу (помилка `TelegramConflictError`).

Як влаштовано:
- **Подвійні записи.** Обмеження `EXCLUDE` у PostgreSQL. Два записи одного майстра на час, що перетинається, неможливі навіть при одночасному натисканні.
- **Нагадування.** Їхній стан зберігається в БД, тому після `docker compose restart` нічого не губиться і не дублюється.
- **Час.** Зберігається в UTC, показується в Europe/Kyiv. Перехід на літній/зимовий час покритий тестами.
